# 반도체 기업에 유용한 소프트웨어·모델

> status: exploring · 2026-09-24 공개 근거로 조사·문제 선정 재시작

엔비디아·삼성전자·SK하이닉스 같은 반도체 기업의 **설계·검증·공정·수율·테스트 전반에서 유용한 문제를 발굴**하고, 소프트웨어 또는 모델로 해결 가능성을 검증합니다. 바이브 코딩은 개발 방법이며, 실제 업무에 대한 유용성이 목표입니다.

## 현재 단계

**공개 자료를 통한 문제 조사와 선정 단계**입니다. 현업 접근 경로가 없는 조건에서 문제의 근거, 기존 대안, 데이터 접근성, 검증 방법을 비교합니다.

2026-09-24 재조사에서는 검색 27회로 반환된 자료 97건을 선별하고, 최종 근거 28개를 바탕으로 8개 후보(P1–P8)를 비교했습니다. 기존 도구가 이미 제공하는 기능과 수정된 오류를 확인해 우선순위를 다시 정했습니다. 자세한 근거와 한계는 [재조사 보고서](literature/problem-selection-2026-09-24.md)에 기록했습니다.

| 우선순위 | 검증할 문제 | 다음 확인 사항 |
|---|---|---|
| **P1 · 우선 검증** | STDF→ATDF 변환에서 검사 결과의 의미 보존 | 원 명세·최신 코드 대조와 최소 사례 재현 |
| P2 · 차순위 | 파형에서 신호값·순서·횟수 등 시간 관계를 정확히 확인 | 공개 코드 접근성과 기존 파형 도구 대비 추가 가치 |
| P3 · 데이터 확인 후 재평가 | 공정 조건 변화 후 예측 신뢰도와 추가 실측 판단 | CMP 데이터 파일·사용 조건·시간 식별자 확보 |

이 순위는 조사자의 **검증 우선순위 제안**입니다. 최신 버전의 실행 재현, 실제 업무 효용, 독립 제품의 수요는 아직 확인하지 않았으며 구현 대상도 확정하지 않았습니다.

## 우선 검증할 문제

STDF는 반도체 검사 결과를 저장하는 형식이고, ATDF는 이를 텍스트로 표현하는 형식입니다. 변환 뒤에도 합격/불합격·재시험 정보가 같은 의미로 읽히는지 확인하려 합니다.

첫 대상은 **PRR(칩 한 개의 검사 결과 레코드)의 빈 재시험 필드 누락 신고**입니다. 공개 신고와 소스가 있어 작은 사례로 확인할 경로가 있지만, 최신 버전에서도 재현되는지는 검증이 필요합니다.

## 다음 진행

1. 원 STDF·ATDF 명세의 필드 순서와 빈 값 의미를 확인하고, 비교할 코드 버전과 기존 수정 적용 여부를 고정합니다.
2. 최소 사례를 기존 도구로 변환해 입력·출력·명세상 기대값을 대조합니다.
3. 기존 라이브러리 수정으로 충분하면 그 범위에서 해결합니다. 반복되는 미해결 사례가 남을 때 별도 검사 도구의 필요성을 검토합니다.

현재 도구로 이미 해결된 문제는 새 구현 후보에서 제외합니다. 새 구현의 효과를 평가할 때는 비교자와 판정 기준을 먼저 protocol로 고정합니다.
