## 선택지 A — 신뢰가능 자율연구 거버넌스 프레임워크로 일반화 (권장)

**Summary**: 4단 게이트(median → LODO → 교차설계 T1 → Codex 의미심사)를 EDA 전용에서
**도메인-불문 "에이전트 산출물 자동 승격 거버넌스" 자산**으로 승격. EDA surrogate 8세대는
"첫 사례 연구"로 지위 변경. 산출물 형태(라이브러리 / 방법론 문서 / 논문+템플릿)는 brainstorming에서 결정.

**Pros**:
- 직전 평가에서 확인된 *유일한 프로덕션-이전가능 가치*에 정면 투자. "LLM 에이전트 산출물을
  사람 개입 없이 언제 믿고 머지하나"는 현재 모든 에이전트 조직의 실전 문제.
- 실증 자산 전부 재사용: gaming 차단(gen-003)·위양성 5건 차단(gen-004~008)·median harness
  진화(gen-002)가 이미 커밋된 증거.
- Operator 1명 + 구독 LLM 리소스에 맞는 범위. 메타 목적(의도공학·co-evolution)과 연속.

**Cons**:
- EDA 도메인 지식 축적 중단(단, archive로 보존).
- LLM eval/guardrail 프레임워크 경쟁 영역 존재 — grounded positioning 조사 선행 필수.
- "제품이 무엇인가"(코드? 방법론? 논문?)가 아직 흐릿 — brainstorming에서 nail down 필요.

## 선택지 B — EDA 프로덕션 surrogate 정면 도전

**Summary**: 설계 수십 개 코퍼스 + 설계-불변 표현 + CircuitNet 류 벤치마크 대비 평가로
실무 투입 가능한 surrogate를 목표.

**Pros**: 원 도메인 유지, 성공 지표 명확(벤치마크 대비 수치).

**Cons**:
- 리소스 차원이 다름(데이터 규모·컴퓨트·EDA 전문성) — 2026-05-29 피벗 사유("1인 과대범위") 재발.
- 7세대 연속 기각 + v2 encoder 2회 기각이 이 벽의 높이를 이미 실증.
- 기존 INTENT의 "절대 PPA가 아니라"를 정반대로 뒤집는 것 — 사실상 새 프로젝트.

## 선택지 C — 논문화·컴파일로 수렴 후 종결

**Summary**: 8세대 + v2 기록을 논문(PAPER.ko.md §7–8)으로 완성하고 status를
clarified(발견으로의 수렴) 또는 killed로 전이.

**Pros**: 최소 노력으로 산출물 확정. 이미 handoff Next Steps 후보. killed도 의도공학상 정당한 결정.

**Cons**: "프로덕션 가치" 질문의 답이 '없음'으로 고정. 게이트·루프 인프라 사장.

## 선택지 D — A + C 순차 (논문으로 v1 닫고, 새 사이클은 A로)

**Summary**: C를 *경계가 있는 마무리 태스크*로 먼저 수행(기존 기록 정합), 그 다음 A의
brainstorming을 새 사이클로 착수.

**Pros**: 무손실 기록 + 새 방향. "리포 유지 + 증축" 패턴(v2 때와 동일)과 일치.

**Cons**: 범위 확대 위험 — 논문화가 길어지면 새 사이클 동력 상실. 순서·시한 경계를 명시해야 함.
