## 1. 가설 (전사 — 재수정 금지)

**H3**: 플로우 실패 진단기(log doctor: LibreLane/ORFS 런 디렉토리→실패 시그니처 매칭→원인·수정 제안)는 공개 실패 사례 코퍼스 백테스트에서 사전 고정 적중률 기준을 충족한다.
**H0**: 홀드아웃 적중률이 기준 미달이다.

## 2. 산출물 정의 (동결)

CLI `flowdoc diagnose`: 입력 = 런 디렉토리 **또는** 로그 파일(`--log` 모드, 백테스트용). 출력 = JSON {단계, top-1 원인, 신뢰도, 수정 제안, 근거 룰 ID·출처 URL}; 룰 미적중 시 `"cause": "unknown"`을 정직하게 출력(강제 추측 금지). 1차 계층 = 결정적 룰 DB(YAML: 패턴→원인→제안→근거 URL 필수), LLM 계층은 본 판정에서 **비활성**(EXPLORATORY 부속 실험으로만). 비스코프: 자동 수정 적용, 상용 플로우, 실시간 예측.

## 3. 개발·누출 통제 (사전 고정)

- **룰 DB 개발은 개발용 32건만 사용.** 룰 개발 에이전트에게 개발용 32건만 발췌한 파일을 제공(발췌 스크립트는 분할 매니페스트 기반, 커밋).
- **누출에 대한 정직한 규정**: git 커밋 순서는 **시간 순서의 감사 증거**이지 누출 부재의 증명이 아니다. Operator는 코퍼스 수집 과정에서 홀드아웃 요약을 이미 열람했고, 개발/홀드아웃 간 동일 실패 계열이 존재할 수 있다(예: C-046↔C-008). 완화: ① 룰 개발은 별도 에이전트가 개발용 발췌 파일만 입력으로 수행 ② **교차 오염 감사(알고리즘 동결)**: 홀드아웃 사례 h가 어떤 개발 사례 d와 {(i) 동일 원 이슈 URL} **또는** {(ii) 동일 저장소(코퍼스 소스 URL의 owner/repo) ∧ 동일 실패 단계(코퍼스 필드) ∧ 시그니처 유사 — 정규화(소문자화, 숫자·16진·파일 경로 토큰을 `#`으로 치환, 공백 축약) 후 문자 3-gram Jaccard 유사도 ≥ 0.5}이면 h를 "related"로 자동 표기. 스크립트는 커밋 체인 ②에 포함. **보고**: 전체 N의 hits/N과 비관련 부분집합 N′의 hits′/N′를 모두 보고(판정은 전체 N 기준, N′는 참고 병기). N′ < 3이면 hits′/N′ 수치는 보고하되 "표본 부족으로 해석 유보" 라벨 부착 ③ 이 한계를 모든 보고에 명시.
- **홀드아웃 입력 패키지 (기계적 추출 — 재량 제거)**: 룰 개발과 무관한 별도 에이전트가 스크립트로 제작: 원 이슈 본문을 `gh api`로 fetch → markdown 코드펜스 블록 전부를 순서대로 연결한 것이 입력(수기 편집 금지). **로그 코드펜스 0개인 사례 = 확보 불가로 기계 제외.** 룰 개발 완료 커밋 → 입력 패키지 커밋 순서 유지(시간 순서 감사).
- **정답 라벨 인정 기준 (필드 값으로 동결)**: 코퍼스 각 사례의 `해결 확인:` 필드 값이 정규식 `^(확인|부분)`에 매칭되는 사례만 홀드아웃 모집단에 유효 — `^미해결` 매칭 사례(예: C-015류)는 기계 제외(괄호 부연은 무시). 라벨 = 코퍼스 "근본 원인" 필드(이미 커밋 — 룰 개발 전 고정).

## 4. 백테스트·판정 (사전 고정)

- 대상(모집단 — 기계 확정): 홀드아웃 14건 중 {라벨 유효(§3) ∩ 로그 코드펜스 ≥1} 사례 전부 = 유효 사례 N. **N < 10 → 실험 무효(T1).** 제외 사유는 사례별 기계 기록.
- 실행: `flowdoc diagnose --log <사례 입력>` 사례당 1회(수정·재실행 금지), 실행 timeout 5분. **크래시·timeout·형식 위반 출력·진단 부재·`unknown` 전부 miss로 계수.** 형식 위반 = 커밋 체인 ②에 고정되는 JSON Schema 파일(`schemas/diagnosis.schema.json`) 검증 실패 — 스키마는 룰 개발 착수 전 커밋, 이후 변경 금지.
- **적중 판정**: (코퍼스 정답 원인, 진단기 top-1) 쌍의 의미 일치를 **Codex 게이트가 심사**(생성≠심사). **일치 정의(동결)**: ① 동일 실패 메커니즘을 지시하고 ② 동일 관여 컴포넌트(툴/설정/셀/넷 계열)를 지시 — 두 요건 모두 충족해야 hit. 단계만 일치·포괄적 서술은 miss. 모호하면 miss가 기본값.
- **판정 결정 트리 (순서대로 첫 매칭 — 전수 포괄, hits = hit 수)**:
  1. **1차 창 만료 시점**(실행 개시 커밋 UTC + 14일)에 {K3 미통과 · N < 10 · 백테스트 미완} → **실험 무효** (T1)
  2. hits ≥ ceil(0.60 × N) → **supported**
  3. ceil(0.40 × N) ≤ hits < ceil(0.60 × N) → **inconclusive** ("부분 유효 — 룰 확장 여지", supported 주장 금지)
  4. hits < ceil(0.40 × N) → **refuted**
- supported/inconclusive/refuted 보고에는 전체 N 결과와 비관련 부분집합 N′ 결과(§3 교차 오염 감사)를 병기.
- 부속 보고(exploratory): 개발용 32건 재대입 적중률(과적합 지표), 단계별 분포, unknown 비율.
