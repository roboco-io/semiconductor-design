## 1. 가설 (research-tree에서 전사 — 재수정 금지)

- **H1**: 체계적으로 설계한 EDA 스킬·하네스를 범용 코딩 에이전트(Claude Code)에 장착하면, FluxBench류 RTL→GDS 태스크에서 하네스 없는 동일 모델 baseline 대비 플로우 완주율이 유의하게(목표 ≥2배) 개선된다.
- **H1.1** (부속): 동일 태스크·동일 모델에서 하네스 설계 변형에 따라 Token ROI가 2배 이상 달라지며, 구독 요금제 기준 실측이 가능하다.
- **귀무 가설(H0)**: 하네스 장착 여부는 완주율에 유의한 차이를 만들지 않는다.

## 3. 변수와 통제

**독립 변수** (Phase A): 하네스 조건 2수준
- **B0 (baseline)**: Claude Code 기본 상태. EDA 관련 스킬·CLAUDE.md 지침·헬퍼 스크립트 없음. 태스크 프롬프트와 기본 도구(Bash 등)만.
- **T1 (하네스)**: B0 + EDA 하네스(스킬 파일: 플로우 실행 절차, 로그 해석 가이드, 실패 복구 전략, 게이트 체크리스트).

**종속 변수**:
- **Primary**: 태스크 완주율 = (성공 시행 수)/(유효 시행 수). 성공 정의: GDSII 생성 + 합성·P&R 완주 + DRC 위반 0 + STA setup/hold 위반 0 (LibreLane 기본 리포트 기준, 결정적 파서로 판정).
- **Secondary** (전부 exploratory): 세션 토큰 사용량, 수정 반복 횟수, 실패 단계 분포, wall-clock.

**QoR 점수 정의 (지금 고정)**: 시행이 §3 성공 기준 미달이면 `Q = 0`. 성공이면 `Q = mean(s_area, s_power)`, 여기서 `s_m = clip(ref_m / design_m, 0, 2) / 2` (m ∈ {셀 면적, 총 전력}, 작을수록 좋음; ref_m = 해당 태스크의 golden RTL을 동일 LibreLane 설정으로 통과시킨 값 — golden RTL·설정은 채점기와 함께 실행 전 커밋). STA는 성공 기준에 이미 포함되므로 Q에 중복 산입하지 않는다.

**Token ROI 정의 (H1.1용, 지금 고정)**: `ROI = Q / (tokens_total / 10^6)` — tokens_total은 세션의 입력+출력 토큰 합(CLI 계측 로그 기준). 조건 수준 ROI는 시행 평균. H1.1의 "토큰 비용 대비 QoR 개선"과 정합. **H1.1 판정 규칙(Phase B)**: 하네스 변형 2종 이상에서 `max(ROI)/min(ROI) ≥ 2` (min>0일 때) 또는 min=0이고 max>0이면 supported; 그 외 refuted.

**통제 (전부 실행 개시 전 커밋으로 고정)**:
- 동일 모델·버전: 실행 개시 커밋에 모델 ID·Claude Code 버전·reasoning effort를 기록하고 Phase A 종료까지 변경 금지. 도중 강제 업데이트 발생 시 해당 시점 이후 시행은 전부 무효 → 동일 버전으로 전체 재실행.
- 세션 격리: 시행마다 새 세션, 공유 상태 없음(작업 디렉토리 초기화 스크립트로 보장).
- 시행 순서: 사전 커밋된 고정 스케줄 `A1:B0,T1,B0,T1,B0,T1 → A2:T1,B0,T1,B0,T1,B0 → A3:B0,T1,...` (교대 + 태스크별 선행 조건 교차).
- 인간 개입 0. 세션 상한: wall-clock 2시간(초과 시 종료). 재시도 없음 — 시행당 세션 1회.
- **무효 vs 실패 (열거형, 사전 고정)**: (a) 환경 장애(툴 크래시·디스크·PDK 손상 등 에이전트 외적 원인, 로그로 입증) → 무효, 동일 셀 재실행 허용 (b) 인간 개입 발생 → 무효, 재실행 허용 (c) 세션 상한 초과·에이전트 자체 포기·오답 → **실패로 계수** (d) 그 외 사유로의 무효 처리는 금지. **재실행 총상한**: 사유 불문 셀당 1회 · Phase A 전체 합계 3회. 상한 소진 후 발생한 무효 셀은 결측으로 두고 §5 동수 N 규칙으로 처리.
- 오염 통제: 태스크 스펙은 공개물 원문 대신 파라미터 변형(비트폭·상수·인터페이스 시그니처 변경)을 적용, 변형 내용은 실행 전 커밋.

**교락 요인 인지**: 하네스 작성자 = 실험자. 완화: ① 하네스는 실행 개시 커밋 전에 커밋, 실행 중 수정 금지 ② 성공 판정은 결정적 스크립트(생성≠심사) ③ 태스크 스펙·채점기는 하네스 작성 **이전에** 커밋(하네스를 채점기에 과적합시키는 순서 차단 — 커밋 순서로 증명).

## 5. Phase A 게이트 규칙 (사전 고정 — 4-way, N = 조건당 유효 시행 수)

우선순위 순서로 평가 (위 규칙 충족 시 아래 평가 안 함):

1. **환경 무효**: 두 조건 모두에서 A1의 성공 시행 0 이고 실패 원인이 환경 기인(채점 로그 판정) → 실험 무효, Experiment Design 백트랙.
2. **Headroom 부족(REVISE)**: `B0 성공 수 > N/2` → ≥2배 개선이 산술적으로 불가능한 영역 → 태스크 난이도 상향 후 Phase A 재설계. (N=9이면 B0 ≥ 5, N=6이면 B0 ≥ 4)
3. **방향 신호(Phase B 진행)**: T1 성공 수 > B0 성공 수 (전체 집계) → Phase B 설계 착수.
4. **무신호/역전(Reflection)**: T1 ≤ B0 → Reflection으로 이동, 하네스 설계 가설 재검토. H1 자체는 미판정 유지(단, 이 결과는 negative 신호로 기록).

**표본 축소 비상 규칙**: 구독 한도 소진 시에만 발동. 셀별 3시행 → 2시행으로 **전 셀 균일 축소**(N=9→6, 총 12세션). 그 외 비대칭 축소 금지. N/2 규칙은 N에 따라 자동 재계산되므로 산술 정합 유지.

**동수 N 규칙 (기한 마감·결측 공통 — 태스크 쌍 절단)**: 판정 시점에 결측이 있으면 **태스크별로** `N_t = min(B0 유효 수_t, T1 유효 수_t)`를 취하고, 각 조건에서 해당 태스크의 스케줄 순서 앞 N_t개만 채택한다. 판정 표본은 N = Σ_t N_t로, 두 조건의 태스크 구성이 항상 동일해진다. N < 6이면 실험 무효.

## 6. H1 정식 판정 규칙 (Phase B에서 적용 — 지금 고정, 변경 금지)

- 표본: 조건당 유효 시행 N ≥ 15 (태스크 확장 또는 시행 수 증가로 달성).
- **판정 결정 트리 (순서대로 첫 매칭 적용 — 전수 포괄)**:
  1. `완주율(T1) ≤ 완주율(B0)` → **refuted** (개선 부재·역효과, 유의성 불문)
  2. Fisher exact(양측) p ≥ 0.05 → **inconclusive** (양의 방향이나 비유의)
  3. (B0 > 0 이고 `완주율(T1) ≥ 2 × 완주율(B0)`) 또는 (B0 성공 0 이고 T1 완주율 ≥ 30%) → **supported**
  4. 그 외 → **refuted** (유의하나 기준 미달: sub-2x, 또는 zero-baseline에서 T1 < 30% — "유의한 개선이나 주장 기준 미달"로 병기 기록)
- 다중 비교: primary 비교는 전체 집계 1건만. 태스크별 분해는 exploratory.
