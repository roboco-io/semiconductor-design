# 트랙 C 계획서 — 플로우 실패 진단기 (flow doctor)

가설: H3 · 근거: [raw/01](../literature/raw/01-tool-gaps-demand.md) (OpenLane #1183 "거의 모두가 겪음"), [raw/04](../literature/raw/04-workflow-tool-gaps.md) (OR #7482 메인테이너의 "actionable advice" 요청)

## 목표

실패한 LibreLane/ORFS 런 디렉토리를 읽어 **알려진 실패 시그니처**(라우팅 크래시, PDN 매크로 훅 누락, 미전원 conb 셀 LVS, 안테나 반복 초과, 혼잡도 초과, 버전 불일치 등)를 매칭하고, **원인 설명 + 수정 config 제안**을 출력하는 CLI. Slack/Discord에 흩어져 소실되는 커뮤니티 진단 지식을 룰 DB로 자산화한다.

## 설계 원칙

- **룰 우선, LLM 보조**: 진단의 1차 계층은 결정적 룰 DB(YAML: 로그 패턴 → 원인 → 제안 → 근거 사례 링크). LLM 해석은 옵션 계층(룰 미적중 시)으로 분리 — 판정 재현성 확보.
- 룰마다 **근거 사례 URL**(원본 이슈/스레드)을 필수 필드로 — 지식의 출처 추적성.

## MVP 스코프

- `flowdoc diagnose <run_dir>`: 단계 판별 → 로그·리포트 파싱 → 룰 매칭 → 원인·제안·근거 출력 (JSON/텍스트)
- 룰 DB v1: 공개 사례에서 추출한 상위 빈도 실패 모드 (LVS·PDN·안테나·라우팅·환경)
- `flowdoc rules lint`: 룰 DB 형식 검증 (기여 받기 위한 기반)

비스코프: 자동 수정 적용(제안만), 상용 플로우, 실시간 모니터링(조기 예측은 후속 — 트랙 A의 예측기와 접점).

## 유용성 판정 기준 (protocol LOCK 항목 — 초안)

| 축 | 기준(초안) | 방법 |
|---|---|---|
| 진단 적중률 (필수) | 홀드아웃 실패 사례에서 top-1 원인 적중률 ≥ 사전 고정 임계값 | 코퍼스를 룰 개발용/홀드아웃으로 **사전 분할** (개발 중 홀드아웃 접근 금지) |
| 재현 가능성 | 룰 개발용 사례는 재현 run으로 수정 제안 적용 시 통과 확인 | 재현 하네스 |
| 외부 사용 | 공개 후 사전 고정 기간 내 외부 사용·룰 기여 발생 | GitHub 지표 |

## 태스크 그래프

```
C1(코퍼스 수집; INFRA-0와 병행 가능) ─→ C1.5(개발/홀드아웃 분할 — 커밋으로 고정) ─→ C3(룰 DB) ─→ C4(백테스트) ─→ [H3 판정] ─→ C5(공개)
INFRA-0 ─→ C2(재현 하네스: 대표 실패를 로컬 재현) ─→ C3
```

| ID | 태스크 | 산출물 | 의존 |
|---|---|---|---|
| C1 | 공개 실패 사례 코퍼스 수집 (GitHub 이슈·open-source-silicon 스레드·TT 사례, 목표 N≥30) | 사례 코퍼스 (URL·로그·해결책) | 없음 (조사성 — 즉시 착수 가능) |
| C1.5 | 개발용/홀드아웃 분할을 무작위로 고정·커밋 (사전등록) | 분할 매니페스트 | C1 |
| C2 | 재현 하네스: 대표 실패 모드를 로컬에서 재현하는 최소 케이스 | 재현 스크립트 | INFRA-0 |
| C3 | 룰 DB v1 + diagnose CLI (개발용 사례만 사용) | v0.1 (public) | C1.5, C2 |
| C4 | 홀드아웃 백테스트 → H3 판정 | 적중률 리포트 | C3 |
| C5 | 커뮤니티 공개(OpenLane discussions·TT Discord) + 룰 기여 가이드 | 공개 포스트 | C4 |

## 리스크

- **코퍼스 편향**: 공개 사례는 해결된 사례로 치우침 — 판정 주장 범위를 "알려진 실패 모드"로 한정.
- **오진 신뢰 훼손**: 제안에 항상 근거 링크 병기, 확신도 표기(rule confidence), 미적중 시 솔직한 "unknown" 출력.
- **적중률 검증 설계**: C1.5의 사전 분할 커밋이 핵심 규율 — git 순서가 사전등록 증명 (프로젝트 불변 원칙과 동형).
