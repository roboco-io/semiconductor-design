## 동작 설계

**① 대상 식별**: `/quiz [대상]` — 인자가 없으면 이 대화에서 가장 최근에 설계·구현·승인된
산출물을 자동 선정하고, 시작 전에 "퀴즈 범위: X"로 확인받는다.

**② 인터뷰 루프 (갭 수렴형)**:
- 핵심 질문 최대 3개로 시작. *설명을 요구하는* 개방형 — "이게 무엇을 하나", "왜 이 방식을
  택했나(대안 대비)", "무엇이 깨지면 이것이 실패하나" 계열. 한 번에 하나씩.
- 답안은 **서술형 자유 텍스트** — AskUserQuestion 사용 금지(선택형 질문 규칙의 명시적 예외).
- 각 답안에서 ⓐ 정확한 부분 ⓑ 갭/오해 ⓒ 모호한 표현을 진단하고, ⓑⓒ를 파고드는 후속 질문을
  이어간다. **힌트 선제공 금지** — 같은 갭이 2회 연속 해소되지 않으면 그때 해설하고 다음 주제로.
- Operator가 "여기까지"·"그만" 등으로 중단하면 즉시 종료 단계로.

**③ 종료·요약·기록**:
- 이해도 요약 3분류: 정확히 이해한 것 / 갭이었던 것(해설 포함) / 다음에 물어볼 만한 것.
- 요약 저장을 물음 (기본: 저장 안 함). 저장 시 `docs/quiz/YYYY-MM-DD-<주제>.md` — 이
  프로젝트에서는 co-evolution 학습 기록으로 커밋 가능.

**④ 태도 규칙**: 인터뷰어이지 채점자가 아님 — 점수·등급 없음, 갭 진단만. 아첨·칭찬 남발 금지,
답안 내용 단순 반복 금지, 질문은 산출물의 *결정과 트레이드오프*에 집중(암기식 세부사항 금지).
